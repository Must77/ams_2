# 02 棱边元与离散梯度 G：本次事故的概念根源

> 前置：01。目标：理解"自由度挂在边上"意味着什么、G 矩阵是什么、
> 以及两种基函数归一化约定为什么会差一个边长因子——修复 1 的全部背景。

## 1. 为什么不用你熟悉的节点元

先回答一个你可能有的疑问：你的二维 MT 正演用节点元一点问题没有——因为 TE/TM 解耦后
未知数是标量（单分量），标量场在节点上连续是物理正确的。**棱边元是三维矢量场特有的
需求**，二维标量问题碰不到它，所以这一篇对你是全新内容，放慢读。

三维的直觉做法：把矢量场 E 的三个分量各当一个标量场，用节点基函数插值（每节点 3 个
自由度）。这对三维电磁场是**错的**，原因是物理连续性要求不匹配：

- 在不同材料（不同 σ、μ）的交界面上，物理上 E 的**切向分量连续，法向分量跳跃**；
- 节点元强制全部三个分量在节点处连续 → 把法向分量也焊死了 → 算出来的场含
  非物理的"伪解"（spurious modes），在电磁界是 1980 年代的著名灾难。

解决方案是 **Nédélec 棱边元（edge element）**：自由度不挂在节点上，挂在**单元的棱（边）上**，
基函数设计成只保证切向连续。这正是 `edges.txt`（每行一条边：边号、两端节点号）存在的原因
——网格的"边表"在节点元世界里不需要显式给出，在棱边元世界里是一等公民。

## 2. 一条边的自由度到底是什么数：两种约定（事故根源）

设边 e 连接节点 n1 → n2，长度 |e|，t 是单位切向。两种常见定义：

**约定 A：Whitney / 环量自由度（本仓库 C++ 代码、eg_1 数据）**

```text
d_e = ∫_e E · t  dl        （场沿边的线积分，"环量"，量纲 = 场×长度）
```

**约定 B：单位切向归一化（对方 Fortran 程序、ams_example 数据）**

```text
d'_e = (1/|e|) ∫_e E · t  dl  ≈  边中点的切向场值   （量纲 = 场）
```

关系：`d'_e = d_e / |e|`。对应的基函数 φ'_e = |e|·φ_e。刚度/质量矩阵是基函数的双线性型
`A_ef = a(φ_e, φ_f)`，所以两种约定下的矩阵相差一个**相似变换**：

```text
A' = S · A · S,    S = diag(|e_1|, |e_2|, ..., |e_N|)
```

两种约定都对、都常见，文献里都用。**但混用而不自知就是灾难**：单看矩阵和右端项完全无法
分辨（方程照样成立、直接解照样能解），只有依赖"矩阵的内部结构"的算法——比如 AMS——
才会突然失灵。这正是本项目卡了几个月的第一层原因。我们最终是从数据里反解出这个 S 的
（06 篇讲怎么反解的）。

## 3. 离散梯度矩阵 G：把"梯度场"翻译到边自由度

01 篇说过 Kr 的零空间是所有梯度场。AMS 预条件器需要显式知道这个零空间，载体就是
**离散梯度矩阵 G**（边数 × 节点数）。它回答：节点标量势 p 的梯度场 ∇p，用边自由度表示
是什么？

约定 A（环量）下用微积分基本定理，答案精确简洁：

```text
(∇p 的环量)_e = ∫_e ∇p · t dl = p(n2) - p(n1)
→ G 每行两个元素：n1 处 -1，n2 处 +1     （纯 ±1 关联矩阵，和图论的关联矩阵同构）
```

约定 B（归一化）下：

```text
(∇p)'_e = (p(n2) - p(n1)) / |e|
→ G' = S⁻¹ · G   （每行是 ∓1/|e|）
```

代码里 `setup_ams()` 构造的是 ±1 的 G（约定 A）。喂给它约定 B 的矩阵，
等于给 AMS 报了一个错误的零空间——后果见 05 篇。

## 4. 必须会的恒等式：Kr·G = 0

"梯度场是 curl-curl 的零空间"翻译成矩阵语言：

```text
Kr · (G p) = 0   对任意节点向量 p        （约定一致时精确成立）
```

这个恒等式是本次诊断的**最强探针**：

- 对 eg_1 实测：`‖Kr·Gp‖` 相对量 ~1e-16（机器精度，恒等式严格成立）→ eg_1 数据与 ±1 的 G 匹配；
- 对 ams_example 实测：~8e-2（完全不成立）→ 数据与 G 失配；
- 换成 G' = S⁻¹G 后实测：~3e-8 → 在数据 8 位精度内精确成立 → 反解出的 S 正确。

一行 numpy 就能跑的测试，终结了几个月的猜测。具体见 06 篇。

## 5. 边方向约定（排除掉的嫌疑）

G 的 ±1 怎么分配取决于"边的方向"（从 n1 指向 n2）。如果组装矩阵时某条边的方向和构造 G 时
相反，该行 G 的符号就错。本算例 `edges.txt` 里 100% 满足 n1 < n2（按节点编号升序定向），
且 06 篇的 patch 反解显示恢复出的对角变换**全部同号**——证明没有方向翻转问题，
失配纯粹是上面的缩放。这条当时是重点嫌疑（交接文档头号怀疑），用数据排除了。
