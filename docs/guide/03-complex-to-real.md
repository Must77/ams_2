# 03 复数系统的实数化与符号约定

> 前置：01。目标：看懂代码里 `[C -M; -M -C]` 这种 2×2 块结构，和"虚部为什么要取负"
> ——这一块曾被列为头号嫌疑，最终证明是自洽的，但约定确实绕，值得一篇说清。

## 1. 为什么不直接用复数算

PETSc 编译期决定标量类型：实数版或复数版，二选一。系统自带的 petsc 包是实数版，
而且 Hypre AMS 也以实数版本最成熟。所以代码把 N 维复数系统改写成 2N 维实数系统。

复数方程 `(Kr + i·Ki)(xr + i·xi) = br + i·bi` 展开实虚部：

```text
Kr·xr - Ki·xi = br
Ki·xr + Kr·xi = bi
```

写成块矩阵（这是"教科书形式"）：

```text
[ Kr  -Ki ] [xr]   [br]
[ Ki   Kr ] [xi] = [bi]
```

但这个形式不对称。乘出来等价的**对称**变体有很多种（行变号、未知数变号的组合），
不同程序选不同变体——于是有了下面的对照表。

## 2. 三方约定对照表（本项目最绕的地方）

**本仓库 C++ 内部（`matshell_mult_a()` 实现的乘法）**：

```text
y_r = C·x_r - M·x_i
y_i = -M·x_r - C·x_i        即块矩阵  [ C  -M ]
                                      [-M  -C ]   （对称！）
```

**对方 Fortran（main.f90 注释里明确写出）**：

```text
[ Kr  -Ki ] [er]   [ Sr]
[ -Ki -Kr ] [ei] = [-Si]    （也对称，但块的内容不同）
```

**adapter 的翻译（`prepare_fortran_upper_1based_inputs` + 求解后处理）**：

```text
C = Kr,  M = -Ki,  内部rhs = (br, bi),  解的虚部取负返回:  xi_物理 = -xi_内部
```

## 3. 验证这套翻译是自洽的（手推一遍，5 行）

把 C = Kr、M = -Ki 代入内部块矩阵的两行方程：

```text
第1行: Kr·xr + Ki·xi = br
第2行: Ki·xr - Kr·xi = bi
```

令 xr = er（物理实部）、xi = -ei（物理虚部取负）：

```text
第1行: Kr·er - Ki·ei = br   ✓ 与复数方程实部一致
第2行: Ki·er + Kr·ei = bi   ✓ 与复数方程虚部一致
```

所以返回前 `out_imag[i] = -out_imag[i]` 恰好把 xi 变回 ei。**整条链路代数正确**，
与对方 main.f90 的形式只是同一复数系统的两种等价实数表示。
（曾被怀疑符号搞反导致不收敛——06 篇讲我们怎么用数据排除的。）

## 4. 时谐约定差异的实测证据

01 篇说 Ki 的符号取决于 e^{±iωt} 约定。实测两份数据**对角虚部符号相反**：

| 数据 | 对角虚部符号 | 含义 |
| --- | --- | --- |
| eg_1（仓库自带） | 100% 为正 | 一种时谐约定 |
| ams_example（对方） | 100% 为负 | 相反的时谐约定 |

这不是错误——adapter 的 `M = -Ki` 翻译对两种符号都代数成立。但它有一个微妙的下游影响：
内层预条件矩阵 `B = C + M = Kr - Ki`。对方数据 Ki 全负 → B = Kr + |Ki|（curl-curl 加正
质量项，对称正定，正是 AMS 设计处理的形式 ✓）。如果将来遇到第三方数据 Ki 为正，
直接套这套约定会得到不定的 B，FCG/AMS 立即崩——**接入新数据源时务必先查对角虚部符号**。

## 5. 警告（继承自交接文档，仍然有效）

不要"顺手修正" `matshell_mult_a()` 的符号。它与 adapter 的翻译、解的后处理、
B 矩阵构造是一个整体，单独改任何一处都会静默破坏其余部分。改动必须四处联动并
重跑 eg_1 黄金回归 + ams_example 残差验证。
